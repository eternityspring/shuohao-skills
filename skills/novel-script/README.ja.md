# novel-script

AIショートドラマのための脚本執筆スキルです。novel-outline が出力した各話のあらすじを、シーンとセリフに書き起こします。前提は最初から組み込まれています：**ドラマを担うのは脚本、撮影を担うのはストーリーボード。**「面白いかどうか」と「どう撮るか」は、まったく異なる速度で反復されます。セリフは絶えず書き直されるため、それをカット割りと結びつけてしまうと、セリフを1行変えるたびにカットを割り直すことになります。そのため、この層にはカット番号もフレームのプロンプトもありません。それらは1つ下の層にあるストーリーボードのスキルの役割です。

ただし、1つの線だけは譲りません：**セリフは散文ではなく、構造化されたデータです。**

- **ビートの流れ** — 各シーンは、アクションのビートとセリフが交互に並ぶ列です。アクションのビート1つにつき出来事は1つ（地の文として記述）、セリフにはすべて話者と演技メモが付きます。セリフはそのまま1行ずつTTSに渡され、アクションのビートは映像がやるべきことを示します
- **各話の尺の予算** — セリフは読み上げ速度（既定では毎秒4.5文字）で、アクションはビートごとの固定見積もり（2.5秒）で換算されます。各話は目標の±15%以内に収まらなければなりません。**3分の回は3分です** — 尺オーバーは生成パイプラインではなく、この段階で検出されます
- **フック＋クリフハンガー** — 各話で明文化され、しかも**フックはラベルではなく最初のビートです**：`hookBeat` がその具体的な映像を担うビートを指定し、その回の最初の3ビート以内（コールドオープン）にあることがゲートで検査されます。アウトラインで約束されたビートは、実際のシーンで回収されなければなりません
- **ボイスオーバーの規約** — `VO` は心の声とナレーションを表し、その声質は演技メモに記します。セリフ集では VO が別にまとめられます

`script.json`、Markdown 形式の脚本、そして自己完結した `script-report.html` を出力します：

## 10項目の品質ゲート、すべてコードで

このリポジトリのほかの3つのスキルと同じ立場です：**モデルが自分で採点するチェックリストには価値がありません。**

| ゲート | ルール |
| --- | --- |
| **各話の尺** | 見積もりが `targetSeconds` の±15%以内（速度、ビートあたりの秒数、許容幅はすべて `params` で調整可能） |
| セリフの長さ | 35文字以下 — ひと息で言えないセリフは、生成もできません |
| 話者の正当性 | 話者はそのシーンのキャストに含まれているか、明示的に `VO` であること |
| フックとクリフの明文化 | 各話に `hook` / `cliff` が必須 |
| **フックは最初の3ビート以内** | `hookBeat` がフックの具体的な映像の現れる位置を指定します — コールドオープンは習慣ではなくゲートなので、フックと実際の冒頭がずれることはありません |
| **各シーンに最低1つのアクションのビート** | セリフだけのシーンはラジオドラマです — 映像がやることがありません |
| 地の文としてのアクション | アクションのビートの中に引用符付きのセリフを書かないこと — セリフはセリフの項目にだけ置きます |
| ビートの回収 | アウトラインがこの回に割り当てたビートは、すべて回収されなければなりません（`--outline` 指定時にチェック。スキップする場合は**明示的に告知**され、黙って飛ばされることはありません） |
| キャラクターの参照 | シーンのキャストがアウトラインに存在すること（`--outline` 指定時） |
| シーンの参照 | シーンが存在し、**照明の状態が美術バイブルに登録されており**、小道具が存在すること（`--art` 指定時） |

セルフテストは、各ゲートが実際に阻止することを証明するため、**すべてのゲートを意図的に破るケース**を用意しています。

## レポート

**レポートは既定で中国語のUIで描画されます。`--lang en` を指定すると完全に英語のレポートになります**（または script.json のトップレベルに `"lang": "en"` を設定します。両方指定した場合は `--lang` が優先されます）。英語モードでは品質ゲートのラベルも翻訳されます（しきい値は計算されたまま）。失敗したゲートの詳細とすべてのデータは、作成されたままの内容で表示されます。

1ページ、幅1600pxのレビュー用ドキュメントです：

- **KPI 帯**：話数 / 見積もり総尺と目標の比較 / セリフ数 / セリフの比率 / シーンの平均の長さ — シーンの切り替え回数は統計値であり、ゲートではありません。AIにとってシーンの切り替えはコストがかからないからです
- **尺ゲージ**：各話に1本のバーがあり、セリフとアクションが積み上げ表示され、目標範囲の帯に重ねられます。尺オーバーと尺不足は、正確な秒数とともに赤で示されます
- **脚本そのもの**：本文で、**1行に2話ずつ**並びます。各話のヘッダー（見積もり / フック / クリフ / 回収したビート）は常に表示されます。シーン部分は300pxで切り詰められてフェードがかかり、話ごとに展開を切り替えられます。ホバーするとセリフごとのコピーボタンが表示されます
- **シーン表**：各シーン × 舞台 × 照明 × キャスト × 見積もり秒数 — 手書きではなく、すべて計算で求められます
- **セリフ集**：**1行に2ブロックずつ**並び、すべてのセリフがキャラクター別にまとめられます。各リストは6行分の高さで、それぞれにスクロールバーが付き、話数・シーンの参照と一括コピーボタンも備えます。`--cast` を指定すると、各キャラクターの見出しに**ボイスプロンプト**のコピーボタンも付きます — セリフと声のデザインが1ページに揃い、そのままTTSに渡せます
- **品質ゲート**のパネル＋ヘッダーのバッジ＋**JSON のエクスポート**（`script.json` をそのままダウンロードします — 編集して、そのまま `render` / `validate` に戻せます）
- すべてのグラフィックはインラインの CSS/SVG で、外部リソースはゼロ、オフラインで開けます

## リレー

```
novel-outline    → outline.json (what)
novel-characters → cast.json    (who)
novel-art        → art.json     (where + what's in their hands)
novel-script     → script.json  (the drama: scenes, beats, lines)
```

`seed <outline.json> --eps 1-3` は、各話の骨組み（目標の秒数、フック、クリフ、回収するビート、候補のシーンとキャスト）を決定的に事前入力します。`validate --outline --art` はキャラクター、ビート、シーン・照明・小道具を相互にチェックします — 美術バイブルに一度も登録されていない照明の状態は、この段階で失敗になります。`render --outline --art` は生の ID の代わりに名前を表示します：**データには ID、画面には名前。**

1つ下の層はストーリーボードのスキルです：カット番号、カットごとの尺、最初のフレームのプロンプト、生成のバッチ分け。

## CLI

```bash
node scripts/novel-script.mjs seed outline.json --eps 1-3
node scripts/novel-script.mjs validate script.json --outline outline.json --art art.json
node scripts/novel-script.mjs checkup script.json
node scripts/novel-script.mjs render script.json --html --outline outline.json --art art.json --cast cast.json > script-report.html
node scripts/novel-script.mjs render script.json --html --lang en --outline outline.json --art art.json > script-report.html
```

レポートのUIは既定で中国語です。`--lang en` を指定すると完全に英語で描画されます。

## 制限事項

- カットなし、カット番号なし、生成プロンプトなし、画像なし — ストーリーボードの層のものは一切含みません
- 尺は**ストップウォッチではなく見積もり**です — ±15%の許容幅はそのためにあります。`params.charsPerSecond` をボイスオーバーのペースに合わせて調整してください
- レポートのUIは中国語と英語に対応しています（`--lang zh|en`、既定は中国語。または script.json のトップレベルの `lang` フィールド）。セリフはドラマの言語に従います
- 1回のバッチで書くのは3話以下にしてください — 脚本はパイプライン全体の中で最も書き直される層です

## セルフテスト

```bash
node scripts/selftest.mjs
```

154個のアサーション — 尺の計算エンジン、統計、ゲートを破るケース、seed、描画（UIの両言語）、エクスポート。モデルの呼び出しはなく、約1秒で完了します。

同梱の例（`examples/渡口-script.json`）は**全6話の完全な脚本**です — 9シーン、123のセリフ、すべての回が±15%の範囲内に収まり、アウトラインと美術のフィクスチャに対してすべてのゲートを通過します。

**macOS + Node 24 でのみテストしています。**
