# novel-characters

長編小説でも短編でも、渡せば登場人物全員分の完全なデザインバイブルが手に入ります。

- **キャスト一覧** — 誰が登場し、どれほど中心的な存在か。1人のキャラクターが呼ばれるあらゆる名前は1人にまとめられます
- **プロフィール** — 性別、年齢、身分、外見、気質、動機、成長の軌跡、人間関係。それぞれに**原文からの逐語引用**の裏付けが付きます
- **デザインプロンプト** — 中英2言語の画像プロンプト＋ネガティブプロンプト＋タグで、Midjourney / SD / GPT-Image にそのまま渡せます。画風はプロンプトに書き込みません。生成時に呼び出し側が、バッチ全体の先頭にスタイル指示を1つ付け加えます
- **ボイスプロンプト** — 声質、音程、話す速さ、訛り、感情に加え、Qwen3-TTS / ElevenLabs Voice Design 向けのボイスデザイン用プロンプト
- **キャラクターのモデルシート** — **1キャラクターにつき1枚**：16:9の画像を3つの領域に分けます。左側（約34%）は証明写真風のバストアップ（顔のデザインの基準）、右上は全身の三面図（ターンアラウンド）、右下は重要なディテールのクローズアップを並べた帯です。切り抜きやすいよう背景は白です。**このスキルは画像を生成しません** — 指示そのものが成果物です
- **人物相関図** — レポート内でキャスト全体を見渡せるビュー：誰が誰と、どのように結びついているか。キャラクターにホバーするとその人物が関わるすべてのつながりがハイライトされ、クリックするとそのプロフィールへ移動します

`cast.json`、Markdown のレポート、そしてダブルクリックするだけで開ける自己完結型の `report.html` を出力します。

**出力言語は自由に選べます**（既定は中国語）：

```
/novel-characters ./book.txt --lang en
/novel-characters ./book.txt --lang ja
```

中国語・英語・日本語のUI文言を同梱しています。**ほかの言語でも動作します** — スキルがUIラベルをその場で対象言語に翻訳し、`cast.json` の `ui` に保存するため、フランス語、韓国語、スペイン語のレポートも英語混じりにならず、完全にローカライズされた形で出力されます。

## 上流

パイプラインでは、**アウトラインがキャラクターバイブルの上流にあります**：

```
novel-outline    → outline.json (what: structure & episodes, who is in)
novel-characters → cast.json    (who: character assets)
```

`outline.json` があれば、まず `seed` から始めてください。その `characters` ブロックで人物一覧はすでに確定しています：

```bash
node scripts/novel-characters.mjs seed outline.json > seed.json
```

引き継がれるのは、アウトラインがすでに決めた内容（キャラクターID、名前、ティア、成長の軌跡、原作のどのキャラクターがこの人物に統合されたか）です。空欄のまま残るのは、この層が担うべき作業（別名、プロフィール、デザインプロンプト、ボイスプロンプト）です。`tier` は `importance` に対応します：`lead` → protagonist、`support` → supporting、`functional` → minor。

**ここでアウトラインのティアを覆さないでください**。ティアがおかしいと思ったら、アウトラインのほうを直します。主役グループの*内部*での振り分けは問題ありません — `lead` には主役たちとメインの敵役が含まれるため、`seed` は全員に protagonist を割り当てます。主役でない人物は、`seedNote` に記録された `role` をもとに major へ格下げしてください。

**アウトラインがなくても問題なく動作します** — このスキルはアウトラインに依存していません。`seed` を飛ばして小説をそのまま渡せば、本文から人物一覧を組み立てます。

## 使い方

インストールについては[リポジトリのREADME](../../README.ja.md)を参照してください。そのうえで：

```
/novel-characters ./your-novel.txt
```

あるいは「この本をキャラクターごとに分解して」と伝えて、パスを渡すだけでも構いません。

### レポートの言語

既定は中国語です。`--lang` を使うか、言葉で頼むだけでも切り替えられます：

```
/novel-characters ./book.txt --lang en
/novel-characters ./book.txt --lang ja
```

中国語・英語・日本語のUI文言を同梱しています。**それ以外のどの言語でも動作します** — スキルがUIラベルをその場で対象言語に翻訳し、`cast.json` の `ui` に保存するため、フランス語、韓国語、スペイン語のレポートも英語混じりにならず、完全にローカライズされた形で出力されます。

言語設定に従わないものが2つあります。**画像とTTSのプロンプトは英語のまま**（これらのエンジンは英語で最もよく機能します）、そして**原文の引用は原語のまま**です（翻訳した時点で証拠ではなくなります）。

## レポートの見た目

3カラムのワークベンチです。上部に検索、左側にあらすじと登場の多い順に並んだキャスト一覧、メインエリアには一度に1人のキャラクターを表示します。

**人物相関図**は左サイドバーの最上部にあり、開くとメインエリアいっぱいに表示されます。そのエッジは各キャラクターの `relationships` から直接作られます — 追加のモデル処理は不要です：

- エッジは**名前*と*別名**の両方で解決されるため、「老伯」と書かれた関係も老周のノードにきちんとつながります
- 同じ2人について片方向ずつ書かれた記述は1本のエッジにまとめられ、両方の言い回しが保持されます
- 各弦には短いラベル（6文字。全文はツールチップとサイドリストに表示）が付きます。キャストが多いとラベルが煩雑になるため、エッジが14本までは既定でオン、それを超えるとオフになり、ヘッダーのトグルで切り替えられます
- キャラクターにホバーするとその人物が関わるすべてのつながりがハイライトされ、行にホバーするとそのつながりだけが強調されます。どちらもクリックするとそのキャラクターが開きます

円形のレイアウトは Node 上で計算され、そのままインラインSVGとして書き出されます — **ライブラリは使用しない**ため、report.html はオフラインでも開ける単一ファイルのままです。

### JSONのエクスポート

上部バーの **Export JSON** ボタンは、`cast.json` とまったく同じ形のデータをダウンロードします — 別のエクスポート形式ではありません：

```json
{ "source": "…", "lang": "zh", "summary": "…", "characters": [ … ] }
```

そのため外部ツールで編集したものを**そのまま `render` に戻して**も、`validate` を通過します。各キャラクターは `sheetImage` のパスを保持しているので、どのシートが誰のものかがわかります。生成したシートの置き場所を `render --images <dir>` で指定すれば読み込まれます（このフラグを付けない場合は、cast.json と同じ階層の `images/` を探します）。

データは `<script type="application/json">` として埋め込まれています。エクスポートはそれを Blob に包んでダウンロードするだけです — **ネットワークリクエストは発生しません**。

## 仕組み

長いテキストを1つのコンテキストウィンドウに流し込むとキャラクターが抜け落ちるため、2段階で処理します：

**パス1 — スキャン**（安価なモデル）
テキストは段落の境目で、互いに重なり合う4万字のチャンクに分割されます。各チャンクを並列にスキャンし、キャラクターの名前、別名、具体的な描写、逐語引用を抽出します。重なりがあるおかげで、チャンクの継ぎ目でちょうど登場したキャラクターも両側から見えます。

**統合**
名前と別名はまとめて索引化されるため、チャンクごとに異なる呼び方も1人の人物に集約されます。完全一致では届かない場合（「陆」と「陆行远」には共通のキーがありません）、スクリプトが包含関係にもとづく `mergeCandidates` を列挙してモデルにレビューさせ、確定した統合は merges.json から決定的に適用されます。キャラクターは言及されたチャンクの数で順位付けされ、この順位が出番の多さの代わりの指標になります。

**パス2 — プロフィール作成**
上位N人（**既定は30人**）のキャラクターだけが、統合されたすべての観察結果をもとに完全なシートを作成されます。各キャラクターには同じキャストの兄弟キャラクターの名前が伝えられるため、外見や声が互いに似通ってしまうことがありません。民族、時代、地域は原作から推定され、画像プロンプトに明示的に書き込まれます — **これらは `--lang` に従いません**。レポートを日本語で出力しても、民国時代の中国の渡し守が日本人の男性になることはありません。

**検証**（省略されることはありません）
3つの厳格なルールがあり、いずれもモデルに任せず、スクリプトで決定的にチェックします：

| ルール | 理由 |
| --- | --- |
| `evidence` は原文の**逐語的で連続した**範囲でなければならない | 捏造を防ぎます。地の文で区切られたセリフをつなぎ合わせてはいけません |
| 画像プロンプトに**キャラクター名を含めてはならない** | 画像モデルは名前に強く引きずられ、あなたのキャラクターではなく自分が覚えているキャラクターを描いてしまいます |
| フィールドごとの**言語の使い分け** | 人が読むフィールドは `--lang` に従い、画像とTTSのプロンプトは常に英語です — そうしないとモデルがぶれます |
| 構造と列挙値 | `importance` はちょうど4つの値のいずれかです |

これらはどれも最初から書いておいたものではありません。どのルールも、実際のモデル出力がそれに違反し、バリデーターがそれを捕まえたからこそ存在しています。

## スクリプトを直接使う

ヘルパーはエージェントなしでも問題なく動作します — エージェントが必要なのは2つのモデル処理だけです：

```bash
node scripts/novel-characters.mjs seed outline.json              # アウトラインがあれば、そこから人物一覧を取り込む
node scripts/novel-characters.mjs chunk book.txt /tmp/wk        # 分割
node scripts/novel-characters.mjs merge /tmp/wk                 # roster-*.json を統合し、統合候補も出力
node scripts/novel-characters.mjs merge /tmp/wk --apply m.json   # レビュー済みの統合を適用
node scripts/novel-characters.mjs assemble /tmp/wk --source Book # card-*.json を cast.json にまとめ、登場の多い順に並べる
node scripts/novel-characters.mjs validate cast.json book.txt   # 検証
node scripts/novel-characters.mjs render cast.json --html       # report.html を生成
node scripts/novel-characters.mjs slug "胡二爷"                  # ファイルシステムで安全な名前
```

## 制限事項

- 1回の実行あたり最大24チャンク（重なりを除いて約93万字）です。それを超える場合は `truncated` と明示的に報告します — 末尾を黙って切り捨てることは**ありません**
- 人が読むフィールドは `--lang` に従います。画像とTTSのプロンプトは**常に英語**です。レポートの言語にかかわらず、これらのエンジンは英語で最もよく機能するためです
- 既定では登場の多い上位30人のキャラクターのプロフィールを作成し、**その全員にシートが作られます** — 1キャラクターにつき1回の呼び出しなので、キャストが多い場合はこれが最も時間のかかる工程です。短くしたい場合は、人数を減らすか、主役だけに絞るよう頼んでください
- **スタイルはプロンプトに含めません。** スタイルは、生成時に下流のジェネレーターがバッチ全体の先頭に付け加える層です。以前はすべてのプロンプトに画風を固定することで多少のぶれを抑えていましたが、そうすると各プロンプトが1つのスタイルに固まり、呼び出し側が選んだスタイルとぶつかってしまいました。そのため、キャスト全体での一貫性はジェネレーター側の課題です。`references/sheet.md` を参照してください

## ファイル構成

```
SKILL.md                 エージェントが読むワークフロー
scripts/
  novel-characters.mjs   chunk / merge / assemble / validate / render / slug
  selftest.mjs           329個のアサーション、モデルは一切呼び出さない
references/
  roster-pass.md         パス1：キャラクターのスキャン
  profile-pass.md        パス2：キャラクターシートの作成（8つの厳格なルール）
  schema.md              シートの構造と、各フィールドが使う言語
  sheet.md               モデルシートのレイアウト仕様
  report-style.md        report.html のデザイン規約
examples/
  渡口.txt                同梱の短編、登場人物4人
  渡口-cast.json          その出力。検証用のフィクスチャも兼ねる
  渡口-cast.md            レンダリング結果。品質の基準線
```

`examples/渡口.txt` では、行商人は常にあだ名でしか呼ばれず、渡し守は一度だけ「おじさん」と呼びかけられます — この物語は、まさに別名の統合を試すために作られています。

## セルフテスト

```bash
node scripts/selftest.mjs
```

チャンク分割、別名の統合、組み立て、ローカライズ、検証、レンダリングにわたる329個のアサーションです。モデル呼び出しなし、利用枠の消費なしで、約1秒で完了します。スクリプトに手を加えたら、何よりも先にこれを実行してください。

**macOS と Node 24 でのみテストしています。** プラットフォーム固有のコードはないため、Linux や古い Node のリリースでも問題ないはずですが、**検証はしていません**。
