# 卡片结构

一张卡 = **frontmatter（机器读）+ 六节正文（人和模型读）**。

## 两族卡

库里有两族卡，`kind` 字段区分，**类目表、正文六节、门都各是一套**：

| 族 | `kind` | 回答什么问题 | 例子 |
| --- | --- | --- | --- |
| 配方卡 | `recipe` | **这场戏这一刀该怎么切** | 过肩正反打、进场三件套、产品环绕 |
| 技法卡 | `technique` | **这个手段是什么、什么时候用、什么时候别用** | 横移、低角度、长焦压缩、逆光剪影 |

**为什么不合成一族**：合了之后类目就同时在说两件事（功能与手段），画廊那张类目 × 能量矩阵立刻失去意义。两族各画各的图——配方卡画类目 × 能量矩阵，技法卡画覆盖表。

**技法卡的完整性是门**。`COVER_DOMAINS` 给每个技法类目定了一个域（运镜域直接就是 20 个 H3 官方词），每张技法卡用 `covers` 认领它讲掉的那几项，**域里少一项 `lint` 就点名**。「这个库覆盖全了运镜」从此是查出来的，不是谁说的。

字段定义与枚举在 `scripts/shot-recipes.mjs` 的 `CATEGORIES` / `APPLIES_TO` / `SIZES` / `CAMERAS` 里，跑 `node scripts/shot-recipes.mjs show <id> --json` 可以把一张卡的机器字段与分节正文打成 JSON 直接用。

## 切字段的判据

按优先级三条，**先记判据，字段自然落位**：

1. **能用字符串比较或集合包含判真假的 → frontmatter；需要语义判断的 → 正文。**「必备短语出现没出现」是 `includes`，进 frontmatter；「前景肩虚化到什么程度算对」是语义，留正文。
2. **跨卡可比较、可索引、可当门输入的 → frontmatter；只在读这一张卡时使用一次的 → 正文。** `category` 要拿去画类目矩阵、要给 `list --category` 过滤；「参考图怎么挂」只对这张卡有意义。
3. **`must_phrases` 是「这张配方每一格都为真」的短语。** 这条是承重墙——它让门可以对配方覆盖的每个分镜无差别检查，不必知道当前是第几格。只在某一格为真的写法一律留正文。

第 3 条的实例：过肩正反打的 `over-the-shoulder` 两格都真，进 frontmatter；「第 2 格前景肩换到右边」只有第 2 格真，写进正文的提示词骨架。

## frontmatter 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | kebab-case，**必须等于文件名**。分镜里的 `recipe` 引用的就是它 |
| `kind` | enum | `recipe`（配方卡）或 `technique`（技法卡）。它决定了后面查哪套类目表、哪套六节 |
| `name` / `name_en` | string | 中英卡名 |
| `one_line` / `one_line_en` | string | 一句话：这个镜头在说什么 |
| `category` | enum | **配方卡**：dialogue / emotion / reveal / entrance / reaction / transition / emphasis / product / talking-head（**类目是镜头的功能，不是题材**）<br>**技法卡**：camera-move / angle / size / composition / lens / lighting / special。**两族的类目不许交叉**，用错族 `lint` 会点名 |
| `covers` | string[] | **技法卡专属，必填**：这张卡讲掉了本类目域里的哪几项（运镜域就是 20 个 H3 官方词）。它是完整性门的唯一输入。**配方卡不许写**——配方讲的是怎么切，不认领词表里的某一项 |
| `applies_to` | string[] | 题材维：drama / product / talking-head / vlog。与类目正交 |
| `energy` | 1–5 | 能量档，画廊矩阵的横轴 |
| `seconds` | [min, max] | 单格时长区间 |
| `cuts` | [min, max] | 这张配方吃几格 |
| `sizes` / `cameras` | string[] | 建议景别与运镜，**是允许集合不是序列** |
| `must_phrases` | string[] | 必备短语，门的核心。≤ 3 条 |
| `must_phrases_zh` | string[] | 每条必备短语的中文释义，**与 `must_phrases` 一一对应、同序同长**。只在中文界面显示；短语本身永远是英文原文 |
| `tags` | string[] | 检索用 |
| `example_frames` | string[] | 示例帧文件名（相对 `cards/frames/`），没有就 `[]` |

## ⚠️ 必备短语的六条硬约束

必备短语是全库唯一被机器强制的东西，写错的代价最大：

1. **≤ 3 条**。短语越多，挂配方的成本越高，用户就不挂了——可选挂载的东西一旦变贵就等于不存在
2. **全小写**，判定时两边都小写化
3. **必须含空格或连字符、长度 ≥ 6**。单个通用词会被当子串误判：`wide` 是 `extreme wide shot` 的子串，写 `wide` 的卡在大远景的格子上会假通过
4. **不许撞保留词**（`RESERVED_PHRASES` = 20 个 H3 官方运镜词 + 5 个景别短语）。景别与运镜**各自已经有一道门在管**，而且那两道门查的位置和本库不同（一个查 `[Shot k]` 段落、一个查 `frame`）——同一个词在两处判定，极易一边过一边不过，用户会以为门坏了

第 4 条推出这个库的存在理由：**配方只描述官方词表描述不了的东西**——前景肩、浅景深、手持质感、材质环绕、光比差。词表能说的，交给词表。

`lint` 逐条检查这四款，违规直接 exit 1。

还有两条，管的不是短语本身：

5. **每条必备短语必须原样、单行出现在本卡「提示词骨架」的代码块里**，中英两份正文各查一次。骨架是给人照抄的，抄下来的提示词必须能直接过 `check`——短语没进骨架，等于这张卡自己都没兑现自己的规矩。**换行截断也算没有**：代码块里为了排版把一条短语拆到两行，肉眼看得见、`includes` 判不出来，这是真踩过的坑（`en/door-threshold` 的 `light differs across the threshold`）
6. **每条必备短语都要有中文释义**（`must_phrases_zh`），一一对应、同序同长，释义里必须有中文，**同一条短语在不同卡上的释义必须逐字相同**。短语本身不能翻译——它要被原样复制进提示词，改一个字母门就不认了；但一整张索引表全是英文，中文读者根本没法用。释义只解释这条短语说的是什么，**不解释为什么要写它**（那是「意图」和「已知坑」的活）

## 建议景别与运镜为什么是集合

`cuts` 是区间（2–3 格），序列长度对不齐；而且集合语义天然只支持「在不在里面」这一种判定，**从结构上就杜绝了有人把它升级成硬门**。它们是语汇不是法条：同一张卡在竖屏与横屏、两人与三人、有台词与无台词的情况下，景别会合理偏移。

## 正文六节

顺序固定，`lint` 查齐全与顺序。**两族各一套**。

### 配方卡

| 节 | 写什么 |
| --- | --- |
| `## 意图` | 这个镜头在说什么——卡片的灵魂，与用什么工具生成无关 |
| `## 提示词骨架` | 切几格、每格的分镜图提示词模板（带 ``` 代码块，必须含 must_phrases 原文）、`[Shot k]` 段落写什么、台词落哪格 |
| `## 参数表` | 四列 `旋钮 / 默认 / 区间 / 调节手感`。旋钮是生成式的（秒数、格数、景别跨度、虚化强度、构图占比），**不写帧数与缓动曲线** |
| `## 参考图约束` | 生成式独有的一节：每格挂哪几张图、图文冲突听谁、前一格能否当后一格的参考 |
| `## 已知坑` | 三列 `病 / 症状 / 治法`，病名二三字命名——与仓库另外五个 skill 的「常见病」惯例合流 |
| `## 示例` | 指向真实分镜片段与示例帧；没有示例帧就写「示例帧未生成。」，不装有 |

### 技法卡

| 节 | 写什么 |
| --- | --- |
| `## 这是什么` | 手段本身。**开头就把它与最容易混淆的那一个划清界限**（横移 vs 横摇、变焦 vs 推轨、俯拍 vs 高角度），给一句能当场判断的话 |
| `## 适用场景` | ★ **这一节是技法卡的核心**。3–5 条具体场景，每条说清哪种戏 / 放在哪个位置 / 配什么情绪。**必须有一段以 `**什么时候别用**：` 开头**（英文 `**When not to use it**:`），`lint` 逐字查这个标记 |
| `## 提示词怎么写` | 带 ``` 代码块（必须含 must_phrases 原文），下面跟要点：哪些字不能省、`[Shot k]` 段落写什么、运镜词给哪个 |
| `## 参数表` | 同配方卡的四列。旋钮是幅度、占比、光比、虚化强度、速度，**不写帧数、缓动曲线、光圈 f 值、ISO、灯位瓦数** |
| `## 已知坑` | 同配方卡的三列 |
| `## 示例` | 同配方卡；对不上真实片段就明说「通用型卡片，短剧样例里没有对应片段」，不硬编 |

**为什么技法卡把「适用场景」排在提示词前面**：手段本身没有「什么时候用」就是废知识。而且**只写什么时候用，读卡的人一定会滥用它**——所以「什么时候别用」是硬要求，不是可选的补充。

## 双语的组织

**机器字段只有一份**：`cards/<id>.md` 的 frontmatter 是唯一来源，语言中立。正文分语言——中文在同一个文件里，英文在 `cards/en/<id>.md`（那份只保留 `id` 一行 frontmatter 做自检）。

`--lang en` 时正文取英文文件，缺了就回落中文并在画廊里明标「English body missing」。这样门永远只读一份机器字段，不存在双语漂移。

## 不变量

以下三条是**这个库对外的判定契约**，写在这里当唯一权威。**任何挂载这套卡库的下游**（同仓库的 `novel-storyboard` 通过 `--shots` 挂载就是一例）都按这三条实现自己那一侧的检查；改动任何一处，下游要同步：

1. **必备短语的判定**：小写化后 `frame.includes(phrase)`，逐条全中才算过
2. **多格配方的表达**：分镜里连续同 `recipe` 的若干格构成一次配方实例，`cuts` 下限是这个连续段的最小长度
3. **缺库时的行为**：没有卡库就明说跳过，不静默通过

## 加新卡

往 `references/cards/` 放一个 `.md`，frontmatter 字段写全（配方卡 16 个，技法卡多一个 covers），六节按顺序写完，英文正文放 `cards/en/` 同名文件，跑 `lint` 直到通过。

**门槛不在格式上**：写卡的规矩见 `card-pass.md`——加新卡要举得出一个真实使用过的分镜片段填进 `## 示例`，举不出来的不是配方，是想法。
