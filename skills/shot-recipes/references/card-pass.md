# 写一张新卡

字段与格式见 `card-schema.md`，`lint` 会逐条查。这份讲的是格式查不了的部分：**什么配当一张卡，以及怎么把它写得有用。**

## 硬规则

1. **一张卡解决一个「这一刀该怎么切」的问题。** 不是一个运镜词（那是词表的活），不是一段风格（那是画风预设的活）。判据：这张卡能不能回答「什么时候用它、切几格、每格提示词怎么写」——三问缺一就不是卡。
2. **加新卡的门槛是举得出真实片段。** `## 示例` 节必须指向一段真的做过的分镜（哪一集、哪一段、哪几格），或者一张真的生成过的示例帧。**举不出来的不是配方，是想法**——想法先留在 issue 里，跑过一遍再进库。
3. **必备短语只写「每一格都为真」的东西。** 三格配方里只有第 1 格为真的写法，写进正文的提示词骨架，不许进 `must_phrases`——它是门的输入，门不知道当前是第几格。
4. **必备短语只描述官方词表描述不了的东西。** 景别与运镜各有一道门在管，卡片不重复设门（`lint` 拦保留词）。前景肩、浅景深、手持质感、材质轮廓、光比差——这些才是配方该说的。
5. **必备短语必须原样落进自己的提示词骨架。** 而且要单行落，别为了排版把一条短语拆到两行——`lint` 逐条查。卡片自己的骨架都没写全短语，抄骨架的人就一定过不了 `check`。
6. **每条必备短语配一条中文释义**（`must_phrases_zh`）。释义只说这条短语指的是什么，**不说为什么要写它**——「为什么」是「意图」和「已知坑」的活，塞进释义那一列表就读不下去了。**别的卡已经用过的短语，照抄它那条释义**，`lint` 会拦不一致的译法。
7. **已知坑写实际踩过的，不写推测的。** 每条坑要能说出症状（画面上看见了什么）和治法（提示词或参考图怎么改）。写不出症状的，说明没踩过。
8. **参数表的「调节手感」是这张表的价值所在。** 只写默认值等于没写——要写「往上调会怎样、往下调会怎样、超过哪里就翻车」。

## 技法卡另外三条

技法卡（`kind: technique`）回答的是「这个手段是什么、什么时候用、什么时候别用」，上面的硬规则照样适用，另加三条：

1. **不许写成摄影教科书。**「低角度让人显得高大」是常识，写它等于没写。这个库要写的是**这个手段在 AI 生成里具体会崩在哪**、**提示词怎么写才钉得住**——「低角度加广角，模型爱把下巴画成两层，写 `chin line clean` 能压住」才是价值。判据：把这一段拿给一个懂摄影但没做过 AI 视频的人看，他要能从里面学到东西。
2. **「什么时候别用」要写得比「什么时候用」更狠。** 只写什么时候用，读卡的人一定会滥用它。`lint` 只能查这一段在不在，查不了写得好不好——写三条真能挡住人的，别写「不适合的场合不要使用」这种废话。
3. **每张卡开头就把它与最容易混淆的那一个划清界限。** 横移 vs 横摇、变焦 vs 推轨、俯拍 vs 高角度、荷兰角 vs 滚转、浅景深 vs 变焦点。**给一句能当场判断的话**——「你想让观众感到空间，用横移；你只想让观众看见旁边还有什么，用横摇」。两张卡互相点名，说法不许打架。

**技法卡与配方卡的交集怎么处理**：过肩机位（技法）与过肩正反打（配方）讲的是同一件事的两层。**后写的那张必须先读先写的那张，划清界限并指向它，而且不许重复声明对方的必备短语**——重复声明会在短语索引里撞车，而且说明你没写出新东西。

## 手感规则（不设门，但决定卡片有没有人用）

- **一句话先写「它在说什么」，不写「它是什么」。**「谁在跟谁说话，一格就交代清楚」比「两人对话的过肩镜头」有用得多——前者告诉人什么时候想起它。
- **意图节要敢下判断。** 「它是对话戏的默认解法，不是特殊技巧」这种话才是卡片的价值；四平八稳的描述读完等于没读。
- **坑要写得具体到画面。**「一致性会变差」是废话，「说到后半段五官慢慢变了」才是能对照的症状。
- **提示词模板要能直接抄。** 给完整的一段英文，不要给「XXX + YYY 的结构」这种伪模板。
- **参数区间要给得起。** 写 2–4 秒就得是真能用的 2 和 4，别把不能用的值写进区间凑数。
- **通用向的卡不要假装短剧向。** 产品与口播的卡就明说短剧样例里没有对应片段，别硬编一个。

## 与「切镜手感」类文档的分工

**这个 skill 是自包含的，可以整个目录拷走单独使用**，不依赖任何别的 skill。但它经常和某份「导演运镜手感」性质的文档一起用——比如同仓库 `novel-storyboard` 的 `storyboard-pass.md`，里面有九条手感（对话切正反打、进场三件套、关键动作独立成切、反应镜头……）。两者是**同一件事的两层**：

- **手感条目是判断口径**：不挂卡库时的最低语汇，读完知道该往哪切
- **卡片是可执行配方**：挂上之后的展开版，带必备短语、参数表、参考图约束、已知坑

所以：**卡片的「意图」节可以与那类手感条目同义，但是不许照抄原文。** 同义是分工，照抄是重复——重复的两处一定会漂。lint 检查不了语义，这条靠写卡的自觉。

单独使用这个 skill 时这一节可以忽略：卡片本身不引用任何外部文档，读卡不需要先读别的东西。

## 常见病

| 病 | 症状 | 治法 |
| --- | --- | --- |
| 词表病 | 卡片通篇在解释 Push In 是什么 | 官方词表已经解释过了；卡片写的是「什么时候用、配合什么构图、会崩在哪」 |
| 万能病 | 适用写成「任何需要强调的场合」 | 适用要窄到能排除：写清楚什么时候**不该**用它 |
| 空坑 | 已知坑写「注意保持一致性」 | 没有症状的坑等于没踩过，删掉或者去跑一遍再回来写 |
| 伪模板 | 提示词骨架写成「主体 + 动作 + 环境」 | 给一段能直接复制的完整英文 |
| 短语通胀 | 必备短语写了五六条把整句提示词都塞进去 | 上限三条；挂配方越贵越没人挂 |
| 帧数病 | 参数表里出现「12 帧」「ease-in」 | 那是程序化渲染的写法；这里的旋钮是秒数、格数、幅度、占比 |
