# novel-outline

小説と目標パラメータを渡すと、5点セットのショートドラマ脚色アウトラインが得られます。

- **脚色方針** — 一行の核心、残す・削る・統合するの各表、リスク対応策、判断の結論（`cutNote`「これはつまり…」／ `mergeNote` 主役一覧の根拠）。重要な判断は**原作からの逐語引用**で裏付けます
- **キャスト表** — アセットの重みで階層分け：主役 ≤ 5、名前付きの脇役 ≤ 10、機能的な役 ≤ 10（名前ではなく顔として、機能でラベル付け）。それぞれに**← 変更記録**（原作の誰に対応するか、誰を統合したか）が付きます
- **ビート表** — 大小のビートを各話に割り当て、間隔は ≤ 3話、空白地帯を作りません
- **各話のあらすじ** — 各話に必須の3項目：あらすじ＋フック＋サスペンス。地の文の叙述のみで、鉤括弧で引用したセリフは範囲外とみなします
- **アセット一覧** — **スクリプトで算出し、モデルが手書きすることはありません**：シーン・キャラクターの使用状況、一度きりのシーンの再利用計画、制作リスクの警告

`outline.json`、Markdown レポート、自己完結した `outline-report.html` を出力します。

## 品質ゲートはコードである

このスキルの核となる姿勢は、**モデルが自己採点するチェックリストには価値がない**ということです。14項目のゲートはすべて `validate` 内の決定的なチェックであり、モデルに読ませる文章ではありません。階層ごとのキャスト上限（主役 1〜5、脇役 ≤ 10、機能的な役 ≤ 10）、物語上の小道具の上限（≤ 8。`props` は任意で、存在しない場合はゲートがその旨を示します）、**話数に応じて変動する**主要シーンの上限（4 + ⌈話数/10⌉ を 5〜15 に丸める — AI制作向けの調整で、シーンは生成されるため、この上限はセット建設費ではなく一貫性アセットを守るためのものです）、一度きりのシーンの再利用計画、ビートの間隔、第1話のフック、大ビートのタイミング、各話3項目、群衆シーンの計画、リスクキーワードの指摘、参照の整合性（役割のないキャラクター、未使用のシーン、未使用の小道具、宙に浮いたIDがないこと）、あらすじに引用セリフがないこと、です。

一律の上限ではなく階層に分ける理由：一律の上限では、*観客が覚えなければならない人物*と、*制作が維持しなければならない一貫した顔の数*が混同されてしまいます。主役の上限は出番と記憶の負荷を守り、脇役・機能的な役の上限は **AIキャラクターアセットのコスト**を守ります。さらにアセット一覧が階層を自動的に作業量へ換算します（主役 → フルのモデルシート、脇役 → バストアップの参考画像、機能的な役 → プロンプトのみ）。名前のないエキストラは表にまったく載せません。機能的な役にアークがないのは正当なことです — 医者は傷を縫うためにそこにいるのですから。

しきい値は定数ではなくパラメータ（`params.thresholds`）です — プラットフォームによって求められるビートのテンポが異なるためです。セルフテストでは**すべてのゲートを一つずつ意図的に破り**、それぞれが実際にブロックすることを証明しています。

## フローの中で最も価値のあるルール

骨組み（筋を削る／キャラクターを統合する／ビートを配置する）は、まず**承認用のクイックドラフト**として提出します — どの筋が消えたか、誰が統合されたか、どの話が大きな見せ場を担うか。ユーザーが了承して初めて各話の執筆が始まり、これは約束ではなくステージゲート（`validate --stage beats`）として強制されます。その後、各話は10話以下のバッチで書かれます。60話を一気に書くと、必ず後半で破綻するからです。

## レポート

レポートはデフォルトで中国語UIで描画されます。`--lang en` を渡すと完全に英語のレポートになります（または `outline.json` のトップレベルに `lang` フィールドを設定します — フラグが優先されます）。UIと品質ゲートのラベルは翻訳されますが、データの内容 — ビートの種類、あらすじ、名前 — は書かれたとおりのまま残り、失敗したゲートの詳細文字列も同様です。英語モードでは品質ゲートのラベルも翻訳されます（しきい値は算出値のまま）。失敗したゲートの詳細とすべてのデータは書かれたとおりのままです。

```bash
node scripts/novel-outline.mjs render outline.json --html --lang en > outline-report.html
```

横幅1600pxの1ページ構成のレビュー文書 — すべてが平らに並び、Cmd+F で検索できます。

- **KPI帯**：話数、ビート、階層別キャスト、主要シーン、制作リスク、脚色モード — 6つの統計タイルを冒頭に配置
- **ビートのリズム**：チャート／表のタブ — デフォルトは物語のタイムライン（大ビートは塗りつぶし、小ビートは淡色、**空白の間隔は軸上に直接注記**され、しきい値を超えると錆色の赤になり、20話ごとに折り返し）、ワンクリックで詳細表へ
- **各話カード**を3列で表示。デフォルトでは最初の3枚をフェードアウト付きで表示し、展開ボタンがあります。各カードにはビートのカプセル、フック／サスペンス項目、シーン・キャスト・リスクのタグが付きます
- **シーン概要**：シーンごとに1枚のカード — 右上に薄い話数、登場状況のストリップ、担うビート、登場するキャスト、または再利用計画
- **重要な判断**：承認すべき3項目を紙面に — どの筋を削ったか（「これはつまり…」の結論付き）、誰を統合したか（キャスト枠の数と主役一覧は**算出値**）、大ビートがどこに来るか（ビート表から自動で列挙し、最初と最後にタグ付け）
- **配役マトリクス**：キャラクターとシーンを1つのグリッドに — 1列を上から下へ読めば、その話に必要なものがわかります
- **アセット換算**：キャストの階層、シーンの環境、制作リスクを準備作業量に換算 — すべて算出値
- **品質ゲート**：ヘッダーのバッジ、失敗があれば失敗バナー、末尾に ✓/✗ の全一覧 — スクリプトで焼き込み
- **JSONのエクスポート**で `outline.json` をそのままダウンロード — 編集して、そのまま `render` / `validate` に戻せます
- **中国語と英語のUIを内蔵** — デフォルトは中国語、`--lang en` で英語
- すべてのグラフィックはインラインのSVG/CSSで、配色はバリデーターでチェック済み。外部リソースはゼロで、オフラインでも開けます

## 点検モード

すでにアウトラインがあり、診断だけしたい場合は次のとおりです。

```bash
node scripts/novel-outline.mjs checkup outline.json
node scripts/novel-outline.mjs render outline.json --html > outline-report.html
```

失敗したゲートがあっても描画はブロックされません — 問題を見せることこそが目的です。

## 長文の扱い

80万字の小説はコンテキストに収まりません。`chunk` は章見出しで巻に分割し（デフォルトでは1巻15章）、各巻を並行して要約したうえで統合します。上限は60巻で、`truncated` を明示的に報告します — 末尾を黙って捨てることはありません。重要な判断は原作を指し示す必要があります（`keep[].evidence`、逐語）— **タイトルから内容をでっち上げることは禁止です**。

## novel-characters との関係

novel-outline は脚色の構造（削る、統合する、ビート配置、各話）を担当し、novel-characters はキャラクターデザイン（プロフィール、画像・ボイスプロンプト、モデルシート）を担当します。

**アウトラインはキャラクターバイブルの上流に位置します**：`characters` ブロックで、誰が登場し、誰が外れ、誰が主役かがすでに決まっているため、キャラクター工程はそのキャスト一覧をもとに作業し、改めて決め直すことはありません。逆方向も可能です — すでに `cast.json` があれば、原作を読み直す代わりにキャラクターの素材として渡せます。このスキルはセリフ、ストーリーボード、生成プロンプトを一切書きません。

## セルフテスト

```bash
node scripts/selftest.mjs
```

249件のアサーション — チャンク分割、バリデーション、ゲートを破るケース、アセット集計、描画（両方のUI言語）、エクスポート。モデル呼び出しはなく、約1秒で完了します。

**macOS + Node 24 でのみテスト済みです。**
