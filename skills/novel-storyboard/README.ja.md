# novel-storyboard

AIショートドラマのためのストーリーボード制作：novel-script のビートの流れを、動画モデルにそのまま渡せる作業リストに変換します。パイプラインの中で動画モデルと直接やり取りする最初の層であり、前提として組み込まれているのは、**ショットは生成するものなので、カットを1つ増やすコストはほぼゼロ**だということです。そしてショートドラマの視聴者の集中力は、約3秒のカットで回っています。そのため3階層の構造をとります。

```
segment = one video-generation call, ≤ 15s, never crosses scenes
 ├─ cuts × 3–5 = intra-segment edits, 2–5s each (hard gate), each claiming script beats
 ├─ frames    = one keyframe per cut: the master frame pinned at 0.00s,
 │              sub-frames pinned at their own cut marks
 └─ H3 prompt = one per segment; multi-picture alignment + [Shot k] cut times audited verbatim
```

- **会話の切り返しは1つのセグメント、1回の生成の中に収まる** — ワイド、Aのクローズアップ、Bのクローズアップはそれぞれ2〜5秒の別々のカットで、各構図は文章頼みの賭けではなく、それぞれのストーリーボードフレームで制御します
- **アラインメント指示は書くものではなく導出するもの** — 複数画像の行（`Picture 2 aligns with the 3.00-second mark…`）と、すべての `[Shot k] At 00:0X.XXX` のカット時刻はカットの尺から計算され、validate が**一字一句**監査します。尺を変えてプロンプトを更新しなければブロックされます
- **プロンプトは公式仕様に従う：デフォルトは英語、1行に1ショット** — 各ショットはカット時刻とともに1行ずつ書きます。台詞、歌詞、画面上のテキストは公式ルールに従って原語のまま残します（`<d>[Chinese] …</d>` で原文どおり）。`promptLang: 'zh'` でプロンプト全体を中国語に切り替えられます。書き方の仕様は `references/h3-prompt.md` として内製化されています — **このスキルは自己完結しており、外部のスキルに依存しません**
- **フレームは創作ではなくアセットの合成** — すべてのフレームには参照マニフェスト、つまりそのフレームを組み立てる元になるシーン／キャラクター／小道具のシートが付いています。**このスキルは画像を生成しません**。プロンプトとそのマニフェストが成果物です

`storyboard.json`、Markdown のショットリスト、そして自己完結型の `storyboard-report.html` を出力します：

## 18項目の品質ゲート、すべてコード

このリポジトリの他の4つのスキルと同じ姿勢です：**モデルが自分で採点するチェックリストには価値がありません。**

| ゲート | ルール |
| --- | --- |
| **ビートの完全カバー** | 脚本のすべてのビートが、順番どおり・連続して・カット単位で、ちょうど1回ずつ割り当てられていること |
| セグメントの尺 | 0 < Σカット ≤ 15秒（1回の生成の上限。`params.maxSegmentSeconds` で調整） |
| **カットの尺** | すべてのカットが2〜5秒 — 約3秒のリズムは助言ではなく**ハードゲート** |
| 台詞が収まる | カットごとに、割り当てられたビートの台詞秒数 ≤ カットの秒数 |
| エピソード合計 | セグメントの合計が脚本の `targetSeconds` の ±15% 以内 |
| 画面内の人数上限 | カットあたり3人以下。それ以上はブレイクダウンの注記が必要 |
| セグメントIDの規律 | `E01-01` 形式で連番 — セグメントIDがそのままアセットのファイル名になる |
| ショットサイズの語 | 中国語のショットサイズの語（例：特写）がカットのフレームプロンプトに含まれていること |
| カメラ用語 | カメラワークは H3 の公式用語（`Push In` / `Pan Left` / `Tracking Shot`…）を使い、**そのカット自身の [Shot k] の段落内**に含まれていること |
| **H3 の構造** | アラインメントの行は**カット構造から導出され、一字一句監査される**。3つのフィールドが順番どおり。すべての `[Shot k]` のカット時刻が、それ以前のカットの尺の累積和と等しいこと |
| **H3 の台詞の原文一致** | 割り当てられたすべての台詞が `<d>` ブロック内に原文どおり含まれていること — 句読点が1つ違うだけで不合格 |
| **プロンプト言語の一貫性** | 本文を `promptLang` と双方向で監査：中国語ドラマを英語で書けば不合格、英語モードに中国語が混ざれば不合格 |
| フレームプロンプトの衛生 | 中国語で、空でないこと（キャラクター名は意図的に含める — 名前は添付のデザインシートを指す） |
| 動画プロンプトに名前を入れない | H3 本文（どちらの言語でも）と Seedance のショットテキストに、キャラクター名や別名を含めない — 両方の公式プロンプトガイドが求めている。`--outline` / `--cast` でチェックし、省略した場合は**その旨を表示** |
| **構図フィールド** | セグメントごとに `blocking`、カットごとにレンズ／カメラ位置／構図／視線／フォーカス／安定性。安定性は列挙値から選ぶ |
| **Seedance のショットテキスト** | すべてのカットの `shot` が中国語で空でなく、タイミング、ショット番号、画像参照、H3 のマーカー、`{}` `<>` `（）` を含まないこと — それらはプログラムが実際の構造から付け加える |
| 参照の整合性 | シーン番号／キャラクター／小道具をすべて脚本のシーンと照合して監査 |
| **ショットレシピ**（任意のマウント） | `--shots <cards dir>` を指定したときのみチェック：カットの `recipe` ID がライブラリに存在し、そのカードの必須フレーズがすべてカットのフレームプロンプトに含まれ、複数カットにまたがるレシピが十分な長さ続いていること。`--shots` なしの場合は省略を**表示**し、「レシピを参照しているカットがない」場合も同様に表示 |

セルフテストでは**すべてのゲートを意図的に破り**、それぞれが実際にブロックすることを証明します。

**ショットレシピは任意の語彙レイヤーです。** カットには任意で `recipe` を付けられます。これは外部の任意のカードライブラリにあるカードIDで、**セグメント単位ではなくカット単位**です。**複数カットにまたがるレシピは、配列ではなく、同じIDを共有する連続したカットの並びとして表現します。** 外部のカードライブラリをインストールしていなくても、すべて動作します。このスキルは自己完結しており、ディレクトリをまたぐインポートの代わりに、25行の制限付きフロントマターパーサーまで自前で持っています。カードが提案するショットサイズやカメラワークは**意図的にゲートの対象外**です — レポートの Recipe 列では逸脱を `≠` で示し（ホバーで提案内容を表示）、`checkup` が注記を出力します。レシピは語彙であって法律ではありません。任意のマウントを厳しくすれば誰もマウントしなくなりますし、**誤ってブロックするゲートは、ゲートがないより悪い**のです。

## ゲートの失敗は蓄積され、`stats` がモデルが最も破るルールを教えてくれる

`validate` と `checkup` を実行するたびに、ゲートの結果が**カレントディレクトリ**の `.gates.jsonl` に追記されます。数十回実行したあとで：

```bash
node scripts/novel-storyboard.mjs stats
```

これは3つの問いに答えます：

| 問い | わかること |
| --- | --- |
| **最も多く発動するゲートはどれか** | そのルールこそモデルが無視しているもの — **直すべきはモデルではなく文言** |
| **一度も発動しないゲートはどれか** | 死んだゲートか、モデルが身につけたルールのどちらか |
| **失敗の詳細はどう見えるか** | 専用のゲートを持たずに繰り返し起きる問題は、この自由記述を読んで初めて浮かび上がる |

これは SkillOpt の「スキルのドキュメントは訓練可能な状態である」という考え方から借りる価値のある唯一のアイデアです：**ドキュメントは一度書いて終わりの仕様ではなく、フィードバックから反復していくもの**です — ただし、その反復には印象ではなく証拠が必要です。ログは証拠を蓄積するだけで、何を変えるかは人間が判断します。

`--no-log` を渡すとスキップします。ファイルに書き込めない場合はこのステップが黙ってスキップされ、検証には影響しません。`.gates.jsonl` はすでに `.gitignore` に含まれています。

## レポート

1ページ、幅1600pxのレビュー用ドキュメントです。レポートはデフォルトで中国語のUIで描画されます。`render` に `--lang en` を渡すと完全に英語のレポートになります（zh / en を内蔵）。これはUIのラベルを切り替えるだけで、H3 プロンプトの言語を制御する `promptLang`（デフォルトは英語）とは独立しています。英語モードでは品質ゲートのラベルも翻訳されます（しきい値は計算されたまま）。不合格ゲートの詳細とすべてのデータは、書かれたままです。

- **KPI バンド**：セグメント数／カット数と平均の長さ／合計と目標の比較／生成バッチ数／台詞を含むセグメント数
- **カットのリズムストリップ**（看板となるチャート）：エピソードごとに1本の帯。**太い区切り線＝セグメントの境界（それぞれ1回の生成）**、スライスの幅＝カットの尺の比率、色の濃さ＝ショットサイズ。スライスをクリックすると、そのセグメントカードにジャンプします
- **セグメントカード**：マスターフレームはトップレベルの `aspectRatio` の取り決めに従います（デフォルトは `16:9`、縦型のボードなら `9:16`。旧来の `_meta.orientation` とフレーム末尾のタグは互換用のフォールバックとして残っています）（未生成の場合は正直なプロンプトのプレースホルダー）。その下にサブフレームのストリップ、そして**50/50の分割**：左にカットの行（開始位置・秒数・ショットサイズ・カメラ・レシピ・**割り当てられた脚本のビートから自動導出される**画面の要約）、右に H3 プロンプトのパネル — 1行に1ショットで、ワンクリックでコピーできます
- **生成バッチ一覧**：同じシーン＋ライティング状態を共有するセグメントが、1枚の環境参照画像を軸に1つのバッチを構成します
- **音声アラインメント一覧**：すべての台詞を**セグメント#カット**に対応づけたもの — TTS 音声を配置するための作業リストで、すべて計算で求められます
- **品質ゲート**パネル＋ヘッダーのバッジ＋**JSON エクスポート**（`storyboard.json` をそのままダウンロード）
- すべてのグラフィックはインラインの CSS/SVG で、外部リソースはゼロ。オフラインで開けます

## リレー — パイプラインはここで閉じる

```
novel-outline    → outline.json    (what: structure)
novel-characters → cast.json       (who: character sheets)
novel-art        → art.json        (where: scene & prop sheets)
novel-script     → script.json     (the drama: scenes, beats, lines)
novel-storyboard → storyboard.json (how to shoot: segments, cuts, frames, H3 prompts)
```

`seed <script.json> --eps 1-3 --aspect 16:9` は、各シーンのビート一覧（番号、ビートごとの秒数、話者）をカット割りのワークシートとして決定的に展開し、公式のトップレベル `aspectRatio` を書き込みます。指定できる値は `16:9` と `9:16` で、デフォルトは `16:9` です。`validate --script` は必須です。`--outline` / `--cast` で名前の禁止チェックが有効になり、`--art` を指定するとシーン名とシートのサムネイルがレポートに入ります。各フレームには、プロンプトと、組み立ての元になる上流のシートを列挙した参照マニフェストが付きます。生成は下流で行います。H3 プロンプトとフレームのセットは、そのまま MiniMax H3 に渡せます。

## CLI

```bash
node scripts/novel-storyboard.mjs seed script.json --eps 1 --aspect 16:9
node scripts/novel-storyboard.mjs validate sb.json --script script.json --outline outline.json --cast cast.json
node scripts/novel-storyboard.mjs checkup sb.json --script script.json
node scripts/novel-storyboard.mjs validate sb.json --script script.json --shots /path/to/cards   # 任意：18番目のゲート
node scripts/novel-storyboard.mjs render sb.json --html --script script.json --outline outline.json --art art.json > storyboard-report.html
node scripts/novel-storyboard.mjs render sb.json --html --lang en --script script.json --outline outline.json --art art.json > storyboard-report.html   # 英語のレポートUI
node scripts/novel-storyboard.mjs export sb.json --script script.json   # セグメントごとのフォルダ：f1..fN.png + prompt.md
```

## 制限事項

- 台詞の執筆や書き直し、デザインシートの作成、動画の生成や編集は行いません
- リップシンクは当面対象外です — それは生成パイプラインの領分です
- 秒数は**見積もりではなく生成の指示**です。セグメントの上限とカットのリズムの範囲は、使用するモデルに合わせて `params` で調整してください
- レポートUIは中国語（デフォルト）と英語を同梱しており、`--lang` で選べます。プロンプトの言語は `promptLang` で別に制御します（デフォルトは英語）
- 本格的に進める前に、最初のセグメントのフレーム一式（3〜5枚）を生成して承認を得てください — 1エピソードは約30〜40フレームあり、美術の方向性を誤るとバッチ全体が無駄になります

## セルフテスト

```bash
node scripts/selftest.mjs
```

336個のアサーション — ビートの展開、H3 の骨格の導出、Seedance の組み立て、統計とバッチ分け、ゲートを破るケース、レシピカードの解析とマウント、seed、描画（両方のレポートUI言語、フレーム枠のアスペクト比）、H3 と Seedance のエクスポート。モデルの呼び出しはなく、約1秒で実行できます。

同梱の例（`examples/渡口-storyboard.json`）は、第1話の完全なストーリーボードです — 10セグメント、34カットで脚本の全35ビートを割り当て（カットあたり約3.5秒）、目標120秒に対して119秒、生成バッチ2つ、すべてのセグメントに完全に監査済みの H3 プロンプトが付いています。

**macOS + Node 24 でのみテストしています。**
